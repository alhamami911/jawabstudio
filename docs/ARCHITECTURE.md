# Jawab Tutorial Builder — الوصف التقني

أداة سطر أوامر تُنتج فيديوهات تعليمية لنظام Jawab ERP (مبني على Odoo) تلقائيًا من ملف سيناريو JSON:
تسجّل الشاشة وهي تنفّذ الخطوات فعليًا على النظام، وتضيف شرحًا مكتوبًا وتكبيرًا عند التفاعل وتعليقًا صوتيًا عربيًا وموسيقى خلفية وبطاقتي عنوان وختام بهوية Jawab، وتُخرج MP4.

## 1. التقنيات والأدوات

| الطبقة | الأداة | الدور |
|---|---|---|
| بيئة التشغيل | Node.js 24 (ESM)، Windows | تشغيل كل شيء؛ يُستخدم `process.loadEnvFile()` لقراءة `.env` |
| اللغة | TypeScript 7 + `tsx` للتشغيل و`tsc --noEmit` للفحص | لا يوجد build، ولا اختبارات آلية |
| أتمتة المتصفح | Playwright 1.64 (Chromium بلا واجهة) | تنفيذ الخطوات وتسجيل الفيديو (`recordVideo`، VP8، 1280×720) |
| معالجة الوسائط | `ffmpeg-static` (ffmpeg 6.1.1: libx264, aac, amix, adelay, loudnorm, sidechaincompress) | دمج الصوت والموسيقى وترميز MP4 |
| الصوت | ElevenLabs REST API (`eleven_multilingual_v2`)، خطة مدفوعة | المزوّد الوحيد؛ تعليق صوتي بلهجة سعودية، وVoice Design لإنشاء صوت من وصف (أُزيل Edge TTS من المشروع) |
| النظام المستهدف | Jawab ERP (Odoo) على `samar.jawab.pro`، المسار `/jawab` | يُسجَّل عليه فعليًا؛ يُستعلم عنه بـ JSON-RPC (`/web/dataset/call_kw`) |
| موسيقى | مُولَّدة بالكود (`scripts/voice/generate-music.mjs`) أو ملف يضعه المستخدم | خالية من حقوق النشر عند التوليد |

لم تُربط أي خدمة أخرى (لا CI، ولا تخزين سحابي، ولا قواعد بيانات).

## 2. مسار العمل (Pipeline)

```
scenario.json
   │
   ▼  record.ts
 1. توليد التعليق الصوتي لكل جملة (ElevenLabs) وتخزينه مؤقتًا، وقياس مدة كل مقطع
 2. تسجيل دخول في سياق متصفح منفصل بلا فيديو → حفظ الجلسة (storageState)
 3. حساب المتغيرات الفريدة بـ JSON-RPC (مثل أول كود حساب شاغر)
 4. سياق التسجيل: بطاقة العنوان فورًا، ثم تنفيذ الخطوات
      لكل خطوة: شرح مكتوب ← تكبير نحو العنصر ← إطار تمييز ← انتظار بقدر مدة الصوت ← تنفيذ ← تصغير
 5. بطاقة الختام
   ▼
 output/<id>/raw.webm + events.json (توقيت بدء كل مقطع صوتي) + steps.md + audio/*.mp3
   │
   ▼  scripts/to-mp4.mjs
 6. ffmpeg: adelay لكل مقطع ← amix(normalize=0) ← loudnorm -16 LUFS ← H.264 (CRF 20)
 7. تمريرة ثانية: موسيقى (loudnorm -30 LUFS) تنخفض أثناء الكلام (sidechaincompress) ← fades ← نسخ الفيديو دون إعادة ترميز
   ▼
 output/<id>/<id>.mp4
```

## 3. بنية الكود

- `src/record.ts`: المنسّق الرئيسي (دخول، متغيرات، تسجيل، توقيت الصوت، كتابة events.json).
- `src/overlay.ts`: JavaScript يُحقن في كل صفحة: بطاقة العنوان والختام، شريط الشرح، إطار التمييز، والتكبير.
- `src/tts.ts`: التوليد عبر ElevenLabs، تخزين مؤقت بمفتاح SHA-1 من الصوت والنموذج والنص، وقياس مدة كل مقطع.
- `src/types.ts`: نوع السيناريو والخطوات (`goto`, `click`, `fill`, `select`, `hide`, `wait`).
- `scripts/`: `to-mp4.mjs` و`generate-music.mjs` و`list-voices.mjs` و`design-voice.mjs` و`delete-account.mjs`.
- `scenarios/_template.json`: قالب الحلقة. `assets/`: الشعار والموسيقى.

أوامر: `npm run record -- scenarios/x.json` · `npm run mp4 -- x` · `npm run voices` · `npm run voice:design` · `npm run music:gen` · `npm run typecheck`.

## 4. قرارات تصميمية تستحق المراجعة

1. **التكبير بـ CSS** (`transform: scale` على عنصر `html`) وليس بمعالجة الفيديو لاحقًا؛ ليبقى الشريط المكتوب ثابتًا. الشريط والإطار يُرسمان في طبقة `popover` العليا لئلا يتأثرا بالتحويل. أثر جانبي: القوائم المنبثقة في Odoo (Popper) تُحسب مواضعها بقياسات مكبّرة، فنُطلق حدث `resize` بعد التصغير لتصحيحها.
2. **توقيت الفيديو يتبع الصوت:** الصوت يُولَّد قبل التسجيل، فيبقى الشرح على الشاشة بقدر مدة الجملة + نصف ثانية، وتُسجَّل أوقات البدء لتُستخدم في الدمج.
3. **الدخول خارج الفيديو:** سياق منفصل ثم `storageState`، فلا تظهر بيانات الدخول في التسجيل.
4. **قيم فريدة** تُستعلم من النظام نفسه (`search_count`) بدل عدّاد محلي، فلا يتكرر كود الحساب.
5. سكربت الحقن نص JS خام لا دالة TypeScript، لأن `tsx` يضيف دوال مساعدة (`__name`) تفشل داخل الصفحة.
6. الكلمات الإنجليزية بين أقواس تبقى مكتوبة ولا تُنطق (الصوت العربي ينطقها بشكل سيئ).

## 5. المخاطر والقيود

**موثوقية**
- الاعتماد على محددات CSS (selectors) لواجهة Odoo؛ أي تحديث للواجهة قد يكسر السيناريو. لا توجد إعادة محاولة ولا إصلاح ذاتي، وفشل خطوة يوقف التسجيل.
- كل تسجيل **ينفّذ عمليات حقيقية** (ينشئ بيانات). لا يوجد تنظيف تلقائي إلا سكربت حذف الحسابات.
- لا اختبارات آلية، ولا CI، والمشروع **غير مُرسَل إلى git** (لا commits بعد).

**جودة الإخراج**
- الدقة 720p والترميز الخام VP8؛ لا قصّ تلقائي لفترات الانتظار.
- لم يُستمع إلى الصوت والموسيقى المولَّدة بشريًا؛ اللهجة السعودية تأتي من وصف الصوت في Voice Design وقد تختلف عن المعاينة، والموسيقى المركّبة بالكود بديل مؤقت.

**أمن وخصوصية**
- كلمة مرور Jawab ومفتاح ElevenLabs في `.env` نصًّا صريحًا (خارج git عبر `.gitignore`).
- نص الشرح يُرسَل إلى ElevenLabs لتحويله إلى صوت.
- مفتاح ElevenLabs بصلاحيات جزئية (لا يملك `voices_read` وقت آخر فحص)؛ يُستحسن مفتاح بأقل الصلاحيات اللازمة (Text to Speech).
- `ffmpeg-static` ينزّل ملفًا تنفيذيًا (نحو 80 ميغابايت) أثناء التثبيت (postinstall script).

**تكلفة وترخيص**
- ElevenLabs: الخطة الآن مدفوعة (التفاصيل والحصة الشهرية غير موثّقة هنا). الصوت المعتمد أُنشئ بـ Voice Design ويستهلك خانة صوت. يجب التحقق من شروط الاستخدام التجاري للخطة وحقوق المحتوى المُولَّد، ومن استهلاك الأحرف لكل تسجيل (إعادة التسجيل تعيد استخدام الجمل المخزّنة).

## 6. أسئلة مقترحة على المستشار

1. هل يُفضَّل بدل محددات CSS استخدام أداة مدمجة في Odoo (Tours) أو اختبارات تكامل رسمية لتوليد الخطوات بشكل أكثر ثباتًا؟
2. استراتيجية بيانات الاختبار: بيئة مخصصة تُستعاد من نسخة قبل كل تسجيل بدل الحذف اليدوي؟
3. هل ElevenLabs هو الخيار الأنسب للنشر التجاري، أم تُضاف طبقة بديلة (مثل Azure Speech الرسمي) لتفادي الارتباط بمزوّد واحد؟
4. إدارة الأسرار: هل يكفي `.env` أم يلزم مدير أسرار، خصوصًا إن اشتغل أكثر من شخص؟
5. رفع الجودة إلى 1080p أو أعلى مع بقاء التكبير سليمًا، وقصّ أوقات الانتظار آليًا.
6. هل يُشغَّل التسجيل في CI على خادم، وما الأثر الأمني لبقاء جلسة دخول فيه؟
7. حفظ الفيديو والمصادر: git للكود فقط أم أيضًا للمخرجات، وأين تُنشر الفيديوهات؟
